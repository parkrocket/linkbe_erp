# 신입 월차 자동 부여 — 설계

- 작성일: 2026-10-30 / 상태: 사용자 승인(대화)
- 선행: 잔여 장부(`2026-10-30-balance-ledger-design.md`), 인사 정보(`2026-10-30-member-profile-design.md`, 입사일·고용형태)

## 결정 사항 (사용자)
- 링크비 방식: **입사한 해 12/31까지, 매달 1일에 연차 +1**. 첫 부여는 입사 후 처음 맞는 1일(3/15·3/1 입사 → 4/1). 다음 해 1/1은 관리자가 연차·휴가 탭에서 일괄 덮어쓰기
- 대상 고용형태: 정규직·계약직·인턴·미지정(NULL). 프리랜서·외주 제외
- 알림: `#hibye-관리` 월 1회 요약
- 개근 여부는 데이터가 없어 검사하지 않음 — 예외는 관리자 조정
- 법(근로기준법 제60조 제2항)은 입사일 기준 1개월 개근마다 1일 — 회사 방식과 차이 있음, 회사 규정은 노무 확인 권장

## 규칙
매달 1일 00:05 KST, 다음을 모두 만족하는 직원에게 `user_stip + 1`(NULL은 0으로):
- `user_status = 'approved'`
- `user_doe`가 올해 1/1 이상 **이번 달 1일 미만** (12월 입사·입사 예정자 제외, 입사 연도 최대 11일)
- `employment_type IS NULL OR IN ('regular','contract','intern')`

## 안전장치
- **월 1회 보장**: 장부에 같은 직원의 `kind='grant'`, memo `YYYY-MM 월차 자동 부여`가 있으면 건너뜀(재시작·중복 실행 안전). 대상 행 `FOR UPDATE` 트랜잭션
- **놓친 달**: 서버 시작 시 **이번 달 몫만** 실행(지난 달 소급 없음 — 과다 부여 방지)
- 운영(`NODE_ENV=production`)에서만 실행 — 로컬도 운영 DB를 쓰므로
- 장부 `actor_mb_no = 0`(시스템), 화면에 '자동'

## 데이터
`lk_balance_log.kind`에 `grant` 추가 (`migrations/2026-10-30-balance-log-grant.sql`, 인사 정보 마이그레이션과 함께 사용자가 실행)

## 화면
이력 창 종류 라벨 `자동 부여`, 변경자 `자동`
